# 의도 포착

문제와 원하는 결과를 사용자 언어로 확인한다. 저장 방식과 승인·Git 정책은 프로젝트 루트 `AGENTS.md`를 따른다.

## 진행

1. `AGENTS.md`, `design/registry.json`, `design/work-state.json`과 전체 공통 제약을 읽는다. 관련 ID의 현재 승인본·최신 제안·근거·예외를 구분한다.
2. 이미 알려진 답은 다시 묻지 않고, 필요한 질문을 한 번에 하나씩 한다. 문제, 영향 대상, 성공 기준, 보존할 동작, 범위 밖을 확인한다.
3. 구현 아이디어와 문제 정의를 구분한다. 사용자가 말한 구현 제안도 잃지 않도록 제안 항목으로 연결하되 이미 승인된 해결책으로 취급하지 않는다.
4. 모르는 내용은 `question` 항목으로 남기고 판단 주체를 내용에 적는다. 긴급 요청이나 “업데이트해줘”를 포괄 승인으로 해석하지 않는다.
5. 이해한 내용을 짧게 확인받고, 항목별 JSON의 `requirement`, `constraint`, `question`으로 저장한다. 승인된 내용만 승인 근거와 해당 ID·revision을 연결해 `accepted`로 기록한다.
6. 저장 직전 기준점을 다시 비교하고, 원본·관계·색인·작업 상태를 일괄 갱신한다. 재조회와 검증 후 변경 ID·미결·검증 결과를 보고한다. 저장을 이유로 커밋·PR을 만들지 않는다.

승인된 의도를 구체적인 요구사항과 검증 기준으로 정리할 때 `spec-authoring`을 사용한다. 다음 단계 수행 권한은 사용자의 요청 범위로 판단한다.

## 사람이 읽는 문서를 요청받은 경우

원본 JSON을 먼저 반영하고 관련 ID·revision 또는 Git commit과 “파생 문서” 표시를 붙인다. `docs/templates/intent.md`의 섹션을 사용한다. 아래는 과거 양식의 가상 예시이며 실제 인물·수치·승인·프로젝트 결정으로 이전하지 않는다. 예시의 상태 표기를 그대로 복사하지 말고 원본의 실제 상태를 표시한다.

```markdown
# Intent: 간편 로그인 개선
작성자: 김민수 (그로스팀) · 상태: draft

## Problem
신규 사용자의 회원가입 과정에서 인증 단계 이탈률이 높다.
지난달 가입 시도 4,200건 중 인증 화면에서 1,100건이 이탈했다.

## Proposed outcome
Google과 Apple 로그인을 추가해 가입 과정을 단순화한다.
인증 단계 이탈률을 절반 이하로 낮추는 것이 목표다.

## Affected users and systems
신규 가입 사용자 / auth-api, mobile-app, user-database

## Constraints
기존 계정과 소셜 계정의 중복 가입을 허용하지 않는다.
현재 세션 구조는 그대로 유지한다.
새로운 PII를 수집하지 않는다.

## Out of scope
기존 사용자의 계정 이전. 관리자 로그인.

## Open questions
기존 이메일 계정을 나중에 소셜 계정과 연결할 수 있게 할 것인가?
```
