# 새 프로젝트 초기 설정

사용자가 이미 답한 내용은 원본에서 찾아 재사용한다. 이름 자리표시자 유무만으로 초기 설정 완료를 판단하지 않는다.

## 진행

1. 프로젝트 루트 `AGENTS.md`, `design/registry.json`, `design/work-state.json`과 전체 공통 규칙을 읽는다. 목적 ID의 항목·출처·승인과 초기 설정 단계 기록을 확인한다.
2. 기록이 없거나 서로 다르면 파일·이전 대응표·실제 설정을 확인한다. 초기 설정이 확인되지 않았다고 설명하고 필요한 질문을 한 번에 하나씩 한다. 모르는 내용을 추측으로 채우지 않는다.
3. 이름·목적·대상 사용자·개발 환경 중 실제 필요한 누락만 확인한다. CODEOWNERS의 예시 계정을 실제 담당자로 간주하지 않는다. 원격 호스트·담당자·도구 설정 변경은 요청 범위와 확인된 정보에 한정한다.
4. 사용자의 실제 답변을 출처로 보존하고, 프로젝트 이름은 registry의 `project_name`, 목적은 항목 JSON과 `purpose_id`에 기록한다. 명시적 지시 범위만 승인 상태로 기록하고 나머지는 제안·미결로 남긴다.
5. 이미 있는 초기 설정 항목을 변경하면 새 revision과 변경 이유를 남긴다. 작업 상태의 초기 설정 단계도 함께 갱신한다.
6. 원본·출처·관계·작업 상태를 일괄 저장하고 색인을 재생성한다. 저장 후 재조회·구조 검증을 수행하고 실제 확인한 설정 범위만 완료로 보고한다.
7. 기존 README의 이름·소개를 채우는 작업까지 요청받았다면 JSON 원본을 먼저 기록한 뒤 해당 부분만 파생 설명으로 갱신한다. 관련 ID·revision과 파생 표시를 남긴다. 요청하지 않은 상세 설명서는 만들지 않는다.

## 보존과 도구

- 이 스킬을 삭제하지 않는다. 완료 기록으로 재질문을 막고, 설정을 변경하거나 중단된 작업을 재개할 때 재사용한다.
- 기존 파일·미커밋 변경을 보존하고, 스킬 변경 시 원본과 생성된 미러의 차이를 확인한다.
- CODEOWNERS·도구 설정에 모르는 계정이나 검증하지 않은 값을 입력하지 않는다. 기술 규격은 관련 공식 근거를 확인한 뒤 반영한다.
- 팀의 사고 사례나 정책 스킬을 미리 만들어 넣지 않는다.
- 사용자가 명령을 직접 실행하거나 파일을 편집하게 하지 않는다. 실행하지 못한 검사는 이유와 함께 알린다.
- 로컬 저장·Git commit·원격 push는 서로 다르다. 명시적 요청 없는 커밋·push·PR을 수행하지 않는다.

구조 설명만 요청받았다면 `project-structure-guide`로 읽고 답한다. 다음 개발 작업은 저장된 목적과 현재 미결 사항을 확인한 뒤 시작한다.
