# 프로젝트 구조와 결정 안내

파일을 바꾸지 않고 저장된 원본을 근거로 답한다. 사용자가 묻지 않은 전체 구조를 강의하지 않는다.

## 조회

1. 루트 `AGENTS.md`, `design/registry.json`, `design/work-state.json`과 전체 공통 제약을 확인한다.
2. 현재 작업과 질문에 관련된 ID를 색인에서 찾는다. 실제 항목의 현재 승인본과 최신 제안을 구분하고 근거·예외·의존 관계를 읽는다.
3. 최근 결정의 변경 이유를 물으면 해당 revision과 이전 revision, 대체 관계, 실제 승인 출처를 확인한다. 기억이나 커밋 시각만으로 승인을 판단하지 않는다.
4. 영향을 물으면 `referenced_by`를 조회하고 관련 항목의 실제 관계를 확인한다.
5. 검색 결과가 없으면 항목 목록·이전 대응표·연결된 보관 원문을 확인한다. 확인하지 못한 것은 “확인하지 못했다”고 말하고 결정 자체가 없다고 단정하지 않는다.
6. `docs/why-this-structure.md`와 기존 문서는 과거 근거다. 현재 원본과 다르면 차이를 알리고, 오래된 도구 설명을 현재의 불변 제약으로 단정하지 않는다.

## 설명

- 프로젝트 이름·목적은 registry와 목적 항목을 읽는다. 초기 설정이 필요한 요청은 `project-bootstrap`으로 구분한다.
- 규칙의 위치, 현재 결정, 그렇게 정한 이유, 남은 미결 사항 중 질문에 필요한 부분만 쉬운 말로 답한다.
- 정책 선택과 검증된 도구 제약을 구분한다. 확인하지 않은 공식 규격을 추측하지 않는다.
- 스킬 원본은 `.agents/skills/`, `.claude/skills/`는 생성된 복사본이다. 수정이 필요한 경우에도 이 읽기 전용 요청만으로 동기화하지 않는다.
- 설계 원본은 JSON이고 상세 Markdown은 요청형 파생 문서다. 문서를 반드시 여러 개 작성해야 한다고 안내하지 않는다.
- 원본이 충돌하거나 저장 미완료 표시가 있으면 현재 상태를 설명하고 확정된 답처럼 제시하지 않는다.
- 이 스킬은 파일·설계 상태·Git을 변경하지 않는다. 보고서 파일 생성도 별도 요청이 있을 때만 한다.
