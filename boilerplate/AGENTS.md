# AGENTS.md

이 파일이 이 프로젝트의 **단일 기준(SSOT)** 이다. 도구별 파일(CLAUDE.md 등)은 이 파일을 참조하고,
자기 도구에만 해당하는 매핑만 추가한다. 같은 규칙을 두 곳에 쓰지 않는다.

규칙이 **왜** 그런지는 `docs/why-this-structure.md`에 있다. 규칙을 바꾸거나 없애기 전에 그 근거를 확인한다.

## 언어

- 모든 산출물·주석·대화는 한국어. 인코딩은 UTF-8.
- **단, 파이프라인 문서(intent/spec/plan)의 섹션 제목은 영어로 고정한다.**
  `Problem`, `Requirements`, `Files` 등. 다음 단계의 에이전트가 안정적으로 파싱하기 위한 규약이며
  본문은 한국어로 쓴다.
  이 제목은 양식(`docs/templates/`)과 스킬 안 템플릿 양쪽에 있으므로 **함께 고친다.**
  `.agents/check-templates.ps1`이 대조한다.

## 소스 및 테스트 코드

- `src/`에는 사용자에게 제공할 완성된 프로그램 소스 코드만 둔다.
- `tests/`에는 `src/`의 동작을 완성·검증하기 위해 작성하는 자동화 테스트 코드를 둔다.
  구현 전에 작성한 테스트도 삭제하지 않고 회귀 검증에 유지한다.
- 일회성 실험, 수동 확인, 임시 변환용 스크립트는 `tests/`에 넣지 않는다.

## 작업 파이프라인

`docs/intent/` → `docs/specs/` → `docs/plans/` 순서로 진행한다. 각 단계는 경계를 넘지 않는다.

| 단계 | 답하는 것 | 여기에 쓰지 않는 것 |
|---|---|---|
| intent | 왜 만드는가 | 라이브러리·스키마·구조 등 구현 이야기 전부 |
| spec | 무엇을 만족해야 하는가 | 파일 목록, 작업 순서 |
| plan | 어떤 파일을 어떤 순서로 | (구현 시작) |

- 세 문서는 **같은 번호·슬러그**로 연결한다. 이게 유일한 연결고리다.
- 미해결 항목은 반드시 이월한다: intent `Open questions` → spec `Concerns`(판단 주체 명시) → plan `Risks`.
  추측으로 채우지 않는다.
- 계획 단계는 **파일을 수정할 수 없는 상태에서** 진행한다. 계획 중 코드가 바뀌는 일이 없어야 한다.
- 3개 파일 이상을 건드리거나 한 문장으로 설명되지 않는 변경은 plan을 남긴다.
  생략은 매번 의식적으로 판단한다 — 기본값이 되면 이 구조는 빈 폴더가 된다.
- **사용자에게 보이는 변화가 배포되면 `CHANGELOG.md`에 작업 번호와 함께 한 줄 남긴다.**
  내부 리팩터링·테스트 추가는 쓰지 않는다. 이 번호가 추적 사슬의 끝을 잇는다.

## 네이밍

- 파이프라인 문서: `NNN-슬러그.md` (예: `002-social-login.md`). 번호는 기존 최대값 +1.
- 결정 기록: `ADR-NNN-제목.md`. 파이프라인과 번호를 공유하지 않는다.
- 커밋 프리픽스: `intent:` / `spec:` / `plan:` / `docs:` / `skill:` / `chore:`
- **개인 설정 파일은 이름에 `.local`을 넣는다** (`settings.local.json`, `config.local.toml`).
  `.gitignore`가 파일명 대신 `.local`을 표식으로 걸러내므로, 이 규칙을 어긴 파일은
  그대로 커밋되어 다른 사람의 환경을 덮어쓴다. 팀 공유 설정에는 `.local`을 붙이지 않는다.
- 작성자·타임스탬프는 git이 기록한다. 문서 안에서 따로 관리하지 않는다.
  **예외는 파이프라인 문서 상단의 `작성자 · 상태` 줄뿐이다** — 발의자가 git을 쓰지 않는
  사람일 수 있어 커밋 작성자와 다르고, 상태 줄은 다음 단계 스킬의 판단 근거다.
- **문서 상태는 `draft` / `approved` 둘뿐이다.** 리뷰 승인 후 **머지 전에** `approved`로 바꾸고
  그 커밋이 머지된다. PR 체크리스트가 이걸 강제한다. 진행 상태(작업 중·완료)는 상태 줄의
  역할이 아니다. 결정 기록(ADR)만 별도 체계를 쓴다 — 표기는 `docs/templates/adr.md`에 있다.

## 스킬

- **원본은 `.agents/skills/<name>/SKILL.md`** — Agent Skills 포맷을 따른다.
  (폴더명 = frontmatter `name`, 소문자·하이픈. `description` 필수.)
- **`.claude/skills/`는 미러다. 직접 수정하지 않는다.** 원본을 고친 뒤 `.agents/sync-skills.ps1`로
  동기화하고 결과를 함께 커밋한다. 두 경로가 어긋나면 도구마다 다른 규칙으로 움직인다.
- 스킬은 여러 도구가 **공용**으로 쓴다. 특정 도구의 고유 기능 이름을 스킬 본문에 쓰지 않고
  동작으로 기술한다. 도구별 매핑은 CLAUDE.md와 `.codex/`가 맡는다.

## 문서 합격 기준

**낯선 사람 테스트** — 이 대화를 한 번도 보지 않은 사람이 문서만 읽고 작업할 수 있는가.

에이전트는 세션 간 기억을 공유하지 않는다. 대화에서 나온 배경을 알아야 이해되는 문장이 있다면
그 배경을 문서에 적어라.

## 하지 말 것

- `.claude/skills/` 직접 수정
- 단계 경계 침범 (intent에 구현, spec에 파일 목록)
- Open questions를 추측으로 채우기
- CLAUDE.md에 프로젝트 규칙 쓰기 — 기준이 둘로 갈라진다
- 확인하지 않은 도구 규격을 사실로 단정하기 — 근거 URL을 함께 남긴다
